findings:
1. **거짓 확신 (False Confidence)**
   - `beta-device-test-analysis.json`의 `assertion_count`가 `0`이며 `required_blank_state_assertions`가 비어 있습니다. 즉, 어떠한 자동화된 기능 어설션 검증도 수행되지 않은 채 단지 프로세스가 "ok"로 종료된 것을 성공으로 판단하는 것은 신뢰할 수 없는 False Confidence입니다.

2. **누락된 검증 증거 (Missing Proof)**
   - **동적 줌 인터랙션 검증 누락**: `input_touch_trackpad_drag_summary_record_count`가 `0`으로 기록되었습니다. 고정된 고배율 줌 상태에서의 재생 성능만 테스트되었을 뿐, 실제 사용자가 재생 중에 줌 변경 드래그를 수행할 때의 렌더 클럭 압박 및 캐시 변동(miss) 수치가 누락되었습니다.
   - **플레이헤드 위젯 배치 테스트 부족**: `playhead_time_widget_placement_sample_count`가 단 `3`회만 수집되었습니다. 22초가 넘는 세션 동안 플레이헤드 위젯의 좌/우 반전 흐름 및 배치 동기화가 다양한 재생 범위에서 충분히 검증되었다고 보기 어렵습니다.

3. **C118 과대주장 (Overclaim) 지적**
   - 릴리스 노트(`RELEASE_v01.00.33.md`) 및 코드 설계에서는 `keeps display capability at 120Hz`라고 명시하고 있으나, 실제 실기기 리포트(`nle-device-timeline-analysis.txt`)의 `c112_display_link_tick_rate_hz_p95`는 `63.93Hz`로 기록되어 있습니다. 120Hz 디스플레이 주사율 지원 기기에서 디스플레이 틱 주사율이 60Hz 수준으로 반막이 났음에도 120Hz 비주얼 주사율 유지를 과대주장하고 있습니다.
   - 또한, 릴리스 노트에는 `Connected-iPad proof is pending for this checkpoint`라고 기재되어 있으나 이미 실기기 테스트 리포트 데이터 폴더가 존재하여 릴리스 문서와 실제 검증 산출물의 형상 불일치가 존재합니다.

4. **플레이헤드/위젯 회귀 위험 (Playhead/Widget Regression Risks)**
   * 고배율 줌(high-zoom) 구간의 렌더 틱 주기를 source-frame cadence 수준(30Hz)으로 억제하면서, 120Hz 화면 갱신 대비 플레이헤드 그리프 라인의 갱신 지연이 발생할 수 있습니다. 수집된 `playhead_grip_line_desync_px_max`가 `0.0`으로 되어 있으나, 이는 동적 제스처 인터랙션이 발생하지 않은 정적 재생 세션의 한계이므로, 스크롤 또는 드래그가 동반될 때 플레이헤드가 끊겨 보이는 비주얼 회귀 위험이 큽니다.
