결론: C118 최적화 방향성에 대한 QA 관점의 Skepticism 검토 완료 및 위험 요소 식별

findings:
1. **C118 최적화 후보별 거짓 확신(False Confidence) 위험**
   - **retained static text compositor**:
     - 정적 텍스트 레이어를 유지하여 SwiftUI 평가 비용을 줄이더라도, 줌 레벨 변동(Timeline Zoom interaction) 시 캐시 무효화(Cache Invalidation Miss)에 대한 안정성 보장이 부족합니다. C116 검증에서는 줌 상태가 고정된 채 48개 노드의 miss가 0으로 나타났지만, 실제 사용자 줌 인/아웃 시나리오에서 miss/rebuild가 치솟아 렌더링 스터터(hitch)가 발생할 위험이 있습니다.
   - **high-zoom render-clock/compositor cost**:
     - 고배율 줌 상태에서 렌더 클럭 틱을 줄이기 위해 coalescing/throttling을 강하게 적용하면, 눈에 보이는 플레이헤드 이동 주기가 떨어져 120Hz iPad 디스플레이의 비주얼 매끄러움(`display_fps=120`) 계약 조건이 깨집니다.

2. **누락된 검증 증거 (Missing Proof)**
   - 재생 중 줌 변경 인터랙션(Zoom-in/out during playback) 시의 CPU p95 부하 추이 및 텍스트 Compositor 캐시 미스 카운트.
   - 120Hz 주사율을 가지는 iPad Pro 실기기 상에서의 NLE 스터터 유발을 정량 감지할 수 있는 Frame drop 카운터 수치 증명.
   - 컴포지터 최적화 시 텍스트 렌더링 스케일(rasterization scale) 축소로 인한 비주얼 흐릿함(blurry text) 방지 검증.

3. **iPad 검증 기대값 (iPad Validation Expectations)**
   - ProMotion(120Hz) 지원 기기에서 CPU p95 부하가 C114(48.5%) 또는 C117(92.6%) 대비 극적인 리덕션을 보장해야 하며, 120Hz 주사율 하에서 프레임 드랍이 `0`이어야 합니다.
   - 줌 레벨과 타임라인 스크롤 속도에 따라 렌더 틱 및 컴포지터 갱신 빈도가 유연하게 동적 coalescing 되는 메트릭을 `analyze_device_timeline_log.py`에서 파싱하여 검증하도록 분석기 필드 확장 필요.

4. **v01.00.15 플레이헤드/위젯 회귀 위험 (v01.00.15 playhead/widget regression risks)**
   - C118 렌더 클럭의 갱신 주기를 제어하거나 스킵할 경우, v01.00.15 사양으로 복구해 둔 플레이헤드 위젯의 고유 폭 제약(`applied width min 108.0`/`220.0`) 및 플레이헤드 탈조 방지 로직이 영향을 받을 수 있습니다.
   - 렌더 틱이 동적으로 생략되는 고배율 줌 구간에서 플레이헤드 핸들과 그리프 라인 간의 위치 괴리(`handle/grip line desync max 0.0px` 제약 위반) 및 위젯 배치 이격 위험이 있습니다.
