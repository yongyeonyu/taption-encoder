# BOKKI Encoder UI 단순화 제안

기준: 현재 소스(main d1d02d5 + 이번 해상도/스케일 모드 변경). 대상 파일은 `Features/Home/HomeView.swift`, `LoadedFilesPanelView.swift`, `HomeMenuSheetView.swift`.

## 1. 지금 화면이 복잡한 이유

홈 한 화면에 서로 다른 목적의 요소가 9개 층으로 쌓여 있습니다.

| 층 | 요소 | 사용자가 하는 일 |
| --- | --- | --- |
| 1 | 헤더 + 별 배지 + 광고 보기 | 광고/재화 |
| 2 | 상단 배너 광고 | (없음) |
| 3 | Files / Folder / Photos | 영상 가져오기 |
| 4 | 대기열 제목 | (없음) |
| 5 | 파일 카드(행 10개 이상) | 확인 |
| 6 | Output 요약(기어) | 설정 |
| 7 | 인코딩 버튼 | 실행 |
| 8 | 하단 배너 광고 | (없음) |
| 9 | Exit | 종료 |

문제는 세 가지입니다.

1. **결정 지점이 흩어져 있습니다.** 영상을 넣고, 출력을 고르고, 실행하는 세 단계가 한 화면에 동시에 있습니다. 지금 무엇을 해야 하는지 화면이 말해 주지 않습니다.
2. **엔진 내부 용어가 사용자 언어로 노출됩니다.** `Path HW`, `Path SW Plan Ready`, `Audio Copy`, `Output Plan Ready`, `Readiness`, `Probe` 같은 값은 개발자용입니다. 사용자는 "이 영상이 변환되는가"만 알면 됩니다.
3. **설정 시트의 조작 방식이 제각각입니다.** 해상도는 메뉴, 용량은 팝오버+슬라이더, 형식/오디오는 메뉴입니다. 같은 급의 결정인데 세 가지 다른 제스처를 배워야 합니다.

## 2. 제안 원칙

1. **한 화면에 결정은 하나.** 화면은 `비어 있음 → 목록 → 인코딩 → 완료` 4개 상태만 갖고, 상태마다 주 버튼은 하나입니다.
2. **엔진 용어는 접는다.** 기본 화면에는 `영상 이름 · 길이 · 원본 크기 → 예상 크기`만. 코덱/경로/준비 상태는 `Help > Diagnostics`로 내립니다.
3. **설정은 한 줄로 합친다.** 해상도 + 용량 + 형식 + 오디오를 "Quality" 하나로 묶고, 나머지는 `Advanced` 안에 넣습니다.

## 3. 화면별 변경안

### 3.1 홈(비어 있음)

지금: 9개 층.
제안:

```
        BOKKI
   영상을 압축합니다

   ┌──────────────────────┐
   │   +  영상 추가        │   ← 주 버튼 1개
   └──────────────────────┘
     파일   폴더   사진        ← 보조 3개, 작은 텍스트 버튼
```

- 상단/하단 배너는 **한 개만** 남깁니다(하단 고정). 두 개는 화면의 절반을 광고가 차지합니다.
- 별 배지 + 광고 보기는 헤더 우측 아이콘 하나로 합칩니다(탭하면 시트).
- Exit는 헤더 좌측 `⋯` 메뉴로 내립니다.

### 3.2 홈(목록 있음)

지금: 파일 카드가 이름·용량·길이·컨테이너·영상 형식·해상도·프레임률·오디오·코덱 경로·출력 요약을 모두 보여 줍니다.
제안: 카드 한 줄을 3개 정보로 줄입니다.

```
[썸네일]  IMG_4821.MOV            12.4 MB → 6.1 MB
          4K · 60fps · 0:38          1080p · Auto
```

- 두 번째 줄은 **원본 요약**, 오른쪽은 **결과 요약**입니다. 이 한 줄이 "무엇이 어떻게 바뀌는가"를 전부 답합니다.
- 코덱/경로/준비 상태는 카드를 길게 눌러 `정보` 시트에서 봅니다(기존 `LoadedFilesPanelView`의 상세 행을 그대로 재사용).
- 파일이 여러 개면 상단에 `3개 · 예상 18.3 MB` 합계 한 줄.

### 3.3 출력 설정 시트

지금: Resolution / Size / Format / Audio + 요약 + 각주.
제안: 두 덩어리.

```
Quality
┌──────────────────────────────────────────┐
│ 원본 그대로            4K · 12.4 MB       │
│ 1080p · Auto          1920×1080 · 6.1 MB │  ← 선택
│ 1080p · Small         1920×1080 · 2.4 MB │
│ 720p  · Auto          1280×720  · 2.9 MB │
│ 직접 지정              ─────●──── 6 MB    │
└──────────────────────────────────────────┘

화면 채우기   [ 여백 | 채우기 | 늘리기 ]      ← 모양이 다를 때만 표시
Advanced ▸   (형식 · 오디오 · 프레임률)
```

- 해상도와 용량을 **한 목록의 한 행**으로 합칩니다. 두 개의 컨트롤을 오가며 조합을 상상하던 일이 사라지고, 행마다 예상 크기가 바로 보입니다.
- `직접 지정`을 고르면 그 행 아래에만 슬라이더가 펼쳐집니다.
- fit/fill/stretch는 원본과 결과의 모양이 다를 때만 나타납니다(이번 변경으로 자동 판단).
- Advanced는 기본 접힘. 형식·오디오·프레임률은 대부분 기본값을 씁니다.

### 3.4 인코딩 / 완료

- 인코딩: 진행률 + 남은 시간 + 취소. 그 외 정보 없음. 파일별 진행은 목록 행에 얇은 바로 표시.
- 완료: `3개 완료 · 18.3 MB` + `저장 위치 열기` / `공유` 두 버튼. 실패한 파일만 빨간 행으로 남깁니다.

## 4. 정리(삭제·이동) 목록

| 대상 | 처리 |
| --- | --- |
| `Path HW/SW`, `Audio Copy`, `Readiness` 배지 | `정보` 시트와 `Help > Diagnostics`로 이동 |
| 상단 배너 광고 | 삭제(하단만 유지) |
| 별 배지 + 광고 보기 버튼 | 헤더 아이콘 1개로 통합 |
| Exit 버튼(하단 전체 폭) | `⋯` 메뉴로 이동 |
| Output Settings의 각주 2줄 | `Quality` 목록 하단 1줄로 축약 |
| 파일 카드의 10개 행 | 3개 정보 + `정보` 시트 |

## 5. 적용 순서

| 단계 | 내용 | 위험 |
| --- | --- | --- |
| P0 | 파일 카드를 3정보 행으로 축소, 상세는 기존 시트 재사용 | 낮음(표시만 변경) |
| P0 | 출력 설정을 `Quality` 단일 목록으로 통합 | 중간(선택 모델은 그대로, 뷰만 교체) |
| P1 | 배너 1개·별/광고 통합·Exit 이동 | 낮음 |
| P2 | 빈 화면/완료 화면 상태 정리 | 중간(상태 머신 손댐) |

P0만 해도 화면당 결정 수가 4개에서 2개로 줄고, 사용자가 배워야 할 제스처가 3종에서 1종으로 줄어듭니다.

## 6. 하지 말아야 할 것

- **설정을 더 접는 것.** 해상도·용량은 이 앱의 핵심 가치라서 숨기면 안 됩니다. 접을 것은 진단 정보입니다.
- **자동화를 늘리는 것.** "알아서 고르기"는 이미 Auto가 합니다. 화면에서 없앨 것은 선택지가 아니라 잡음입니다.
